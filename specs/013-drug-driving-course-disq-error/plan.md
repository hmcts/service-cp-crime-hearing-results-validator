# Implementation Plan: DR-DISQ-013 Drug Driving Course-Reduction Disqualification Error

**Branch**: `CRA-345-drug-driving-disq-block` | **Date**: 2026-10-16 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/013-drug-driving-course-disq-error/spec.md`

## Summary

Add validation rule `DR-DISQ-013` that raises an ERROR-level offence-scoped issue whenever a drug
driving offence (one of five CJS codes: RT88584, RT88586, RT88584B, RT88340, RA88045) has a
course-reduction disqualification result (`DDRCO` or `DDRCOT`) recorded against it.

**Technical approach**: New `DrugDrivingCourseReductionPreprocessor` (presence-based: fire when
DDRCO/DDRCOT is found) + new `DrugDrivingContext` record + one new field on `PreprocessingDefinition`
(`courseReductionShortCodes`) + YAML rule file + Liquibase migration. The CEL condition is
`qualifyingCount > 0` → ERROR. No changes to controllers, services, or DTO contracts.

## Phase 0: Research — Resolved

See [research.md](research.md) for full decision log. Key outcomes:

1. **New preprocessor required** — DR-DISQ-002 is absence-based (fires when extended-test code is
   missing); DR-DISQ-013 is presence-based (fires when DDRCO/DDRCOT is present). Distinct logic
   requires a distinct `ValidationPreprocessor` implementation.

2. **New context record** — `DrugDrivingContext` (4 fields) replaces reuse of
   `DisqualificationContext` (8 fields, wrong naming for this use case).

3. **`PreprocessingDefinition` extended** — new field `courseReductionShortCodes: List<String>`.
   Backward-compatible; existing builders unaffected.

4. **Result category filter: none** — DDRCO/DDRCOT is unlawful on the offence regardless of the
   result line's category. Filtering by category-F would miss non-final lines.

5. **CEL condition: `qualifyingCount > 0` → ERROR** — binary trigger, no graduated severity.

## Phase 1: Design & Contracts

See [data-model.md](data-model.md) for full record and YAML designs.

### DrugDrivingContext (new record)

| Field | Type | Description |
|-------|------|-------------|
| `offenceId` | `String` | The offence this context represents |
| `qualifyingCount` | `long` | 1 if drug driving offence has DDRCO/DDRCOT; else 0 |
| `qualifyingOffenceIds` | `List<String>` | `[offenceId]` when qualifying; else empty |
| `allOffenceIds` | `List<String>` | Always `[offenceId]` |

CEL variable exposed: `qualifyingCount`.

### DrugDrivingCourseReductionPreprocessor

**Qualifier**: `drug-driving-course-reduction`
**Algorithm**: for each offence, check `offenceCode ∈ relevantCodes` AND `anyShortCodeIn(lines, courseReductionCodes)` (all lines, no category filter).

### DR-DISQ-013.yaml (rule contract)

```yaml
rule:
  id: "DR-DISQ-013"
  title: "Drug driving offence with course-reduction disqualification"
  priority: 13000
  enabled: true
  preprocessing:
    type: "drug-driving-course-reduction"
    relevantOffenceCodes:
      - RT88584
      - RT88586
      - RT88584B
      - RT88340
      - RA88045
    courseReductionShortCodes:
      - DDRCO
      - DDRCOT
  conditions:
    - id: "AC1"
      name: "Drug driving offence with course-reduction disqualification"
      expression: "qualifyingCount > 0"
      severity: ERROR
      messageTemplate: >-
        You cannot add a disqualification with a reduction for attending a course
        to a drug driving offence. Remove this result and add the correct
        disqualification.
      affectedOffenceSet: "qualifyingOffenceIds"
      validationLevel: OFFENCE
```

### API contract impact

No change to endpoint paths, request schema, or response schema. The `validation_rule` table gains
one new row. Error issues in the response body follow the existing `ValidationIssue` shape (already
used by all other rules).
